本地 RAG 威胁模型与验证指南

评估对象是使用 deepseek-r1:7b 的虚构商城客服。原型按关键词检索审核过的文档，模型选择来源，程序校验来源并展示已授权原文。示例角色用于模拟权限，部署时应由可信身份系统提供角色。

数据流与信任边界

  1. 文档接入外部资料进入审核区。原型用批准的摘要锁定本地 JSON 数据。
  2. 检索用户问题进入查询层。先按角色过滤，再根据关键词选择候选。
  3. 模型只将获准候选的内容和问题发送到本机 Ollama。模型只需返回来源编号或空值。
  4. 输出应用校验字段和候选编号，再将获准的原文作为纯文本显示。无资料时统一回退。

保护对象包括语料完整性、内部文档、检索权限与用户可见回答。请求参数、外部文档和模型回复均按不受信数据处理。演示使用虚构资料，角色由命令行指定。

亲自运行并生成报告

将 rag-assistant.cjs 和 knowledge.json 放在同一目录。使用 Node.js 16.20.2 或更新版本，在 PowerShell 中运行下列命令。check 使用固定模拟响应验证程序边界。check --live 会另外调用本地 7B，并写出同目录的 rag-test-report.html。

Set-Location .\rag-lab
ollama list
node .\rag-assistant.cjs check
node .\rag-assistant.cjs ask public "退货期限是多少？"
node .\rag-assistant.cjs ask public "内部工单升级组是什么？"
node .\rag-assistant.cjs ask staff "内部工单升级组是什么？"
node .\rag-assistant.cjs check --live
Invoke-Item .\rag-test-report.html

第二个问答命令应返回统一提示并显示「模型调用 否」。用员工角色重复相同问题，验证授权查询的来源。报告逐项列出通过或失败，结论限于这些虚构用例。

在 Navigator 里核对结果

  1. 打开本地 ATLAS Navigator，点击 +，展开 Open Existing Layer，选择 Upload from local。
  2. 导入 atlas-rag-threat-model.json。按编号找到例如 AML.T0057，查看对应边界、已有控制和待办。
  3. 将自己的报告用例编号和结果补到格子的备注中，再下载更新后的图层。
